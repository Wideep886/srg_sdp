# 強正則圖上界：數值搜尋與精確驗證

[English](README.md)

這個套件由強正則圖參數 **(v, k, λ, μ)** 計算球面上界。其中 `v` 是頂點數，`k` 是度數；相鄰與不相鄰頂點分別有 `λ` 與 `μ` 個共同鄰點。選項 `--points` 表示 SDP 使用的點數，與圖的度數 `k` 不同。

如果這組參數的圖存在，單射的特徵空間嵌入會得到 `v` 個互異的單位向量，且不同向量間只有兩種指定內積。程式計算這類球面配置的點數上界。**若精確驗證的整數上界小於 `v`，就證明圖不存在。** 上界大於或等於 `v` 時，仍不能判定圖是否存在。新輸入直接由四個參數分析，不限於預先列出的案例。

## 1. 先驗證已有證書，不需要求解器

使用 **Python 3.9 或更新版本**；Python 程式只需要標準函式庫。保留整個套件，並在包含 `code/`、`results/`、`extras/` 的資料夾中開啟終端機。從 GitHub 的 **Code → Download ZIP** 下載後，解壓縮資料夾通常叫 `srg_sdp-main`；可以自行改名。

在 macOS 上，先輸入 `cd `，將解壓縮後的資料夾從 Finder 拖入終端機，再按 Enter。執行 `pwd` 確認位置。以下指令都假設目前位於這個資料夾內。

```sh
python3 code/srg.py list
python3 code/srg.py verify --certificate 550_162_75_36
```

`list` 列出下方四份證書。`verify` 重新執行精確檢查，並在 `results/runs/` 建立新報告；不會執行求解器，也不採信保存的 `PASS` 旗標。六點驗證可能需要數分鐘。已有證書保持不變。

| 證書 ID | 參數 | 已保存的整數上界 |
|---|---|---:|
| `351_140_73_44` | (351, 140, 73, 44) | 348 |
| `550_162_75_36` | (550, 162, 75, 36) | 506 |
| `703_182_81_35` | (703, 182, 81, 35) | 592 |
| `1344_221_88_26` | (1344, 221, 88, 26) | 1307 |

四份證書都使用六點、五次模型。更換 ID 即可驗證其他證書。加上 `--independent` 可選擇額外檢查：使用另一套全次數係數公式與整數 Bareiss 矩陣消去法。這支檢查程式不匯入其他專案程式碼；一般的模型建構與驗證程式則共用部分公式程式碼。

## 2. 檢查新的參數組

```sh
python3 code/srg.py inspect --srg 550 162 75 36
```

程式精確檢查參數與譜的必要恆等式，再列出嵌入維度 `n` 與內積 `a,b`。預設選擇維度最小且受支援的**單射**嵌入。可用 `--eigenspace r` 或 `--eigenspace s`，明確選擇較大或較小的非平凡特徵值。

| 狀態 | 意義 |
|---|---|
| `supported` | 通過必要條件檢查，且有受支援的嵌入；不代表圖存在。 |
| `infeasible` | 精確的必要條件不成立；報告會說明原因。 |
| `unsupported` | 超出目前實作範圍；不是不存在性結論。 |
| `invalid` | 輸入或要求的參數不合法。 |

**目前只支援有理數運算。** 判別式不是完全平方數的可行 conference 參數，例如 `(5,2,0,1)`，會產生無理數內積，因此回報 `unsupported`，不以近似值代替。空圖與完全圖也不在這個二距離介面的範圍內。

## 3. 為新的搜尋設定求解器

數值搜尋使用 **SDPA-GMP**，它是使用 GMP 的 C/C++ 求解器。Python 負責建立模型與驗證候選解。檢查已有證書不需要 SDPA-GMP。

請**擇一**設定：指定已有的執行檔，或編譯隨附原始碼。

```sh
python3 code/srg.py setup --solver "/absolute/path/to/sdpa_gmp"
```

```sh
python3 code/srg.py setup --build
```

請將範例路徑換成實際路徑。設定會將執行檔位置存入 `extras/local_settings.json`。執行 `python3 code/srg.py doctor` 可查看 Python、套件與求解器的位置。

編譯需要 macOS 或 Linux/WSL、C/C++ 編譯器與標準建置工具，詳見[編譯需求與來源授權](extras/third_party/README.md)。不需要再下載原始碼。流程會檢查來源雜湊、執行 GMP 測試與求解器範例，並保存日誌。這套編譯流程不支援原生 Windows。

預設編譯目錄為 `extras/solver/`。若套件路徑含空白或 shell/make 特殊字元，請用 `setup --build --prefix "/absolute/path/without_spaces/srg_solver"` 指定其他位置。編譯目錄必須尚不存在。**`setup --build --timeout 1200` 限制整個編譯及其測試的總秒數**；必要時可提高。

## 4. 建立模型、搜尋並驗證

```sh
python3 code/srg.py solve --srg 550 162 75 36 --points 6 --degree 5
```

指令會在 `results/runs/` 建立新目錄，依序建立模型、執行 SDPA-GMP、精確驗證候選解。加上 `--independent` 可執行額外的獨立檢查。四個圖參數可換成任何受支援的輸入；程式不保證每組輸入都能得到不存在性證明。

| 選項 | 預設值 | 意義 |
|---|---:|---|
| `--points` | `min(6,n)` | 介於 `2` 與 `min(6,n)` 的整數。 |
| `--degree` | `5` | 多項式最高次數，須為非負整數。 |
| `--eigenspace` | `auto` | 維度最小的受支援單射嵌入，或明確指定 `r`/`s`。 |
| `--precision` | `1500` | 向求解器要求的位元精度。 |
| `--iterations` | `2000` | 求解器最多迭代次數。 |
| `--epsilon` | `1e-16` | 求解器停止容差，不是證明的接受容差。 |
| `--timeout` | `1200` | 求解器秒數，不包含模型建立與精確驗證。 |
| `--output` | 新目錄 | 可自行指定輸出位置；不覆寫已有目錄。 |

若想先檢查模型，再執行搜尋，把 `solve` 改成 `prepare` 即可。它不需要求解器，並會顯示下一步的 `run` 指令。若要重驗已完成的搜尋，指定該次執行的根目錄與新的報告目錄：

```sh
python3 code/srg.py verify --run "/absolute/path/to/run" --output "/absolute/path/to/new_check"
```

若從其他工作目錄操作，請使用 `code/srg.py` 的絕對路徑，以及輸入／輸出的絕對路徑。含空白的路徑要加引號。預設資源依程式本身的位置定位，不依終端機目前的目錄定位。

## 如何判讀結果

程式會顯示輸出位置。驗證結束後的 `result.json` 包含：

| 欄位 | 意義 |
|---|---|
| `verified` | 要求的精確檢查全部通過。 |
| `certified_integer_bound` | 得到的整數上界；沒有證書時為 `null`。 |
| `nonexistence_proved` | 驗證通過，且上界嚴格小於 `v`。 |
| `verification_summary` | 詳細報告的位置。 |

**求解器成功不等於證明完成。** 搜尋失敗、逾時或精確檢查失敗，都不會給出經驗證的上界，也不能判定圖是否存在。檢查失敗會以非零結束碼離開，並保留診斷資料。較大的模型可能需要更多時間；求解器逾時設定不是整個流程的總時間限制。

## 檢查了什麼？有哪些限制？

驗證程式把印出的十進位數視為精確有理數，加回記錄的對角位移，並重建原始不等式。必要檢查包含矩陣正性、零次矩陣壓縮與提升、每條原始殘差、係數捨入，以及求解器輸出與候選矩陣的對應。

驗證要求矩陣裕量為 `10^-30`、原始殘差嚴格小於 `-10^-26`，皆以精確運算檢查。係數以 600 位有效十進位數輸出，捨入誤差再以有理數稽核。求解器停止容差不會改變這些證明要求。

指定點數以內的所有可實現 Gram 配置都列入不等式，包括奇異配置。對**線性相依的參考配置**，局部函數設為零：這會限制搜尋範圍，可能使上界變弱。零次矩陣保留可實現的邊界標籤；正次項在殘餘範數為零時不產生貢獻，因此可省略這些標籤。空矩陣仍保留在精確模型內，只在傳給求解器時省略，讀回時還原成 `[]`。

[驗證紀錄](extras/VALIDATION.md) 說明實際執行過哪些檢查。軟體測試與檔案雜湊檢查不能取代精確證書驗證。

## 檔案、完整性與來源聲明

| 位置 | 用途 |
|---|---|
| `code/` | Python 程式；從 `srg.py` 開始。[逐檔說明](extras/SOURCE_HISTORY.md)。 |
| `results/certificates/` | 四份已保存的模型、候選解、求解器輸出與歷史報告。 |
| `results/runs/` | 新搜尋與重新驗證報告，需要時才建立。 |
| `results/release_checks/` | 支持已記錄發布檢查的報告。 |
| `extras/third_party/` | 求解器／GMP 來源、來源雜湊與原作者聲明。 |
| `extras/tests/` | 回歸測試與小型測試資料。 |
| `extras/VALIDATION.md`、`extras/SOURCE_HISTORY.md` | 驗證範圍與程式來源沿革。 |
| `extras/SHA256SUMS` | 發布檔案的 SHA-256 內容指紋。 |

歷史紀錄可能含有原始路徑與程式雜湊，用來辨識當時的執行；讀者電腦不必具有相同路徑。本機設定、求解器編譯產物、快取與新實驗輸出不納入 Git。

在專案根目錄執行 `shasum -a 256 -c extras/SHA256SUMS`，可檢查檔案完整性。SHA-256 可發現檔案與隨附清單的差異，但不證明數學正確；若清單與檔案一同被替換，也不能藉此辨識來源真偽。清單不包含自身或使用者執行後產生的檔案。
